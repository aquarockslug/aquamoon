# wm

Aquamoon's river window manager, forked from
[tinyrwm](https://codeberg.org/river/tinyrwm) and implemented in Lua. The
implementation lives in `wm.lua`; protocol bindings and helpers are in `wm/`.

## Dependencies

System dependencies:
- lua (5.4)
- luarocks
- libwayland
- libxkbcommon

The lua-ecosystem dependencies are handled by luarocks:
`cffi-lua`, `firefly/wau` and `luaposix`.

## Layout

| Path | Purpose |
|:-----|:--------|
| `wm.lua` | window manager implementation |
| `xkbcommon.lua` | keysym helper |
| `protocol/*.xml` | river protocol descriptions |
| `protocol/*.lua` | generated by `wau-scanner` |

## Tiling

Windows are tiled automatically in a master/stack layout on the output they
appear on. The first window on an output gets the master area on the left and
the remaining windows are stacked on the right. Moving or resizing a window
with the pointer makes it float; tiled windows are arranged again on the next
manage cycle.

The layout can be tuned with an optional `[layout]` section in
`aquamoon.toml`:

```toml
[layout]
tiled = true        # set to false to start in floating mode
main-ratio = 0.66   # master width, clamped to 0.1..0.9
gaps = 0            # space around and between windows
smart-gaps = true   # no gaps when an output has a single window
```

Layout actions usable in key/mouse bindings:

| Command | Effect |
|:--------|:-------|
| `toggle-tiling` | enable/disable automatic tiling |
| `toggle-floating` | toggle floating for the focused window |
| `float` / `tile` | force the focused window to float / tile |
| `increase-main-ratio` / `decrease-main-ratio` | resize the master area |
| `set-gaps N` | set gaps and disable smart gaps |
| `toggle-smart-gaps` | toggle smart gaps |

The shipped `toml/aquamoon.toml` binds these to:

| Key | Action |
|:----|:-------|
| `Super+Space` | `toggle-floating` |
| `Super+Shift+Space` | `toggle-tiling` |
| `Super+equal` / `Super+minus` | increase / decrease the master ratio |
| `Super+g` | `toggle-smart-gaps` |

## Running

In the aquamoon checkout, `../bin/wm` launches `wm.lua` with the Lua 5.4 module
paths it needs. `~/.config/river/init` execs that launcher, so a normal `river`
start uses the working tree directly:

```sh
river
```

Make sure libxkbcommon.so and libwayland-client.so are present in
`LD_LIBRARY_PATH` (and `river` and `foot` in your `PATH`).

## Optional install

The rockspec is kept for installing outside the checkout:

```sh
eval $(luarocks --path bin)
luarocks --local make
```
